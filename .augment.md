# Zoi AI Ecosystem - Augment Agent Context

> **Specialized context file for Augment AI development agent to understand the Zoi ecosystem codebase structure, patterns, and development workflows.**

## 🎯 Codebase Overview for Augment

**Zoi** is a **production-ready, self-hosted AI ecosystem** built with **Docker Compose microservices**. This file provides Augment with the specific context needed to effectively assist with development tasks.

### Key Technologies
- **Docker Compose**: Microservices orchestration
- **Python**: AI services (LiteLLM, custom agents)
- **YAML**: Configuration management
- **PostgreSQL**: Primary database with pgvector extension
- **Redis**: Caching and session management
- **Qdrant**: Vector database for embeddings
- **Traefik**: Reverse proxy and load balancer

## 🔧 Development Patterns for Augment

### When Adding New AI Models
1. **Primary Config**: `config/litellm/config.yaml`
2. **Pattern to Follow**:
```yaml
model_list:
  - model_name: descriptive-name
    litellm_params:
      model: provider/model-identifier
      api_base: http://service-name:port
      api_key: ${ENV_VAR_NAME}
      max_tokens: 4096
    model_info:
      description: "Clear description"
      use_case: "specific-purpose"
```

### When Modifying Services
1. **Service Config**: Update `apps/stack-name/docker-compose.yml`
2. **Environment Variables**: Add to `.env` file
3. **External Config**: Place in `config/service-name/`
4. **Restart Required**: `docker compose restart service-name`

### When Adding New Services
1. **Choose Stack**: Determine which app stack (core/platform/tools/archon/monitor)
2. **Follow Pattern**:
```yaml
service-name:
  image: official/image:tag
  container_name: service-name
  ports: ["${SERVICE_PORT:-default}:internal"]
  environment: [list of env vars]
  volumes: [config and data mounts]
  networks: [zoi-network]
  restart: unless-stopped
  depends_on: [dependencies]
  healthcheck: [health check command]
```

## 🚨 Critical Dependencies (Always Consider)

### Service Startup Order
```
1. postgres, redis (foundation)
2. qdrant, mongo (data stores)  
3. litellm, ollama, vllm (AI services)
4. traefik, authentik (platform)
5. n8n, openwebui, lobechat (applications)
```

### Network Dependencies
- **All services** must use `zoi-network`
- **Internal communication** via service names (not localhost)
- **External access** via Traefik proxy or direct ports

### Configuration Dependencies
- **Environment variables** in `.env` override defaults
- **Config files** in `config/` directory are mounted read-only
- **Database connections** use service names (e.g., `postgres:5432`)

## 🔐 Security Context

### Authentication
- **API Keys**: Stored in environment variables
- **Master Key**: `LITELLM_MASTER_KEY` for API access
- **SSO**: Authentik for web interfaces
- **Internal**: Services communicate via Docker network

### Best Practices
- **Never hardcode secrets** in configuration files
- **Use environment variables** for sensitive data
- **Mount configs read-only** when possible
- **Follow principle of least privilege**

## 🚀 Performance Considerations

### Resource Usage
- **Memory**: 16GB+ recommended (32GB optimal)
- **CPU**: 8+ cores for good performance
- **Storage**: SSD recommended for databases
- **GPU**: Optional but improves inference speed

### Scaling Patterns
- **Horizontal**: Add more model instances
- **Vertical**: Increase container resources
- **Caching**: Redis for response caching
- **Load Balancing**: Traefik handles distribution

## 💡 Augment-Specific Guidelines

### When Analyzing Code
1. **Check dependencies** in docker-compose files
2. **Understand service relationships** via network connections
3. **Look for environment variable usage** in configs
4. **Consider startup order** for service modifications

### When Suggesting Changes
1. **Maintain microservices architecture** - don't couple services
2. **Use centralized configuration** - update `config/` directory
3. **Follow naming conventions** - lowercase, descriptive names
4. **Include health checks** for new services
5. **Update documentation** when adding features

### When Debugging Issues
1. **Start with service logs** - `docker compose logs service-name`
2. **Check configuration parsing** - validate YAML syntax
3. **Verify network connectivity** - test inter-service communication
4. **Monitor resource usage** - check for memory/CPU constraints

### Code Quality Standards
- **Configuration as Code**: All settings in version control
- **Environment Parity**: Development matches production
- **Graceful Degradation**: Handle service failures elegantly
- **Comprehensive Logging**: Include structured logging for debugging

This ecosystem is **enterprise-grade** and handles **production workloads**. Always maintain these quality standards when suggesting modifications or additions.
